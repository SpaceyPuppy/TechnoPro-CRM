# ADR 007: ORM — Drizzle

## Status
Accepted

## Context
Needed a data access layer for the backend. Options considered: Prisma, Drizzle ORM, Knex (query builder), raw mysql2 driver.

## Decision
Use **Drizzle ORM** for all database operations.

## Rationale
- Pure TypeScript — no binary dependencies (Prisma's Rust query engine caused deployment issues on cPanel in a prior project)
- SQL-like syntax maps directly to the team's existing SQL knowledge
- Full type safety — table schemas infer TypeScript types automatically
- Built-in migration tooling (drizzle-kit)
- Lightweight and fast
- Supports MySQL natively

## Trade-offs
- Smaller community than Prisma (but growing rapidly)
- Relations require explicit joins rather than Prisma's nested `include` syntax
- Fewer tutorials and blog posts available

## Consequences
- Schema defined as TypeScript code in `backend/src/db/schema/`
- Migrations generated and applied via `drizzle-kit`
- No platform-specific binaries to manage during deployment
- Portable across any hosting environment where Node.js runs
